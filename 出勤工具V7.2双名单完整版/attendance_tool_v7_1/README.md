# 出勤工具 V7.2 双名单多图版

出勤工具 V7.2 双名单多图版

一、已有 V7.1 云应用：
解压“更新包”，把 attendance_tool_v7_1 文件夹里的文件上传到 GitHub 中原来的同名文件夹，提交更改。
包括 app.py、core/batch.py、core/export.py，以及新增 utils/paired_roster.py。保留各自子文件夹，不要都放到同一个目录。
例如已有入口为 出勤工具V7.1独立新版/attendance_tool_v7_1/app.py，就在 出勤工具V7.1独立新版 目录上传本包的 attendance_tool_v7_1 文件夹。
只更新独立新版，旧出勤工具应用可继续作为兜底。入口不用更换，目录名 v7_1 保留用于兼容，页面显示 V7.2。

二、全新部署：
解压“完整版”，将 attendance_tool_v7_1 文件夹和 packages.txt 上传到新仓库根目录，不能仅上传 ZIP。
Streamlit 入口填 attendance_tool_v7_1/app.py，Advanced settings 选 Python 3.12。
packages.txt 必须在仓库根目录；若旧仓库根目录已有此文件，合并保留已有内容并补齐本包列出的依赖。
不要上传本地凭据或模型权重。本包不包含这些内容。

三、使用：
分别上传游戏 ID 名单和 YY ID 名单，单列 TXT、CSV 或 XLSX。TXT/CSV 使用 UTF-8 编码。
两个名单第 1 行是同一个人，第 2 行是同一个人，依次对应。可用第一行表头“游戏ID”和“YYID”。
上传后展开对应关系预览，核对顺序；程序能检查数量，不能判断你是否排错了人。
名单不得有空行或重复 ID；数字 ID 请保存为文本，避免 Excel 丢失前导零。
两边名字一样时，两侧上传同一份名单即可。
然后分别上传游戏截图、YY截图，支持多张，点击开始识别。
游戏图只匹配游戏名单，YY图只匹配YY名单，再按行汇总；人工核对显示两个 ID，导出也保留两个 ID。
任一名单或截图变化，都会清除旧结果，需要重新识别。

四、免费版内存：
复用现有 OCR 模型，并串行处理截图；上传原图保留压缩数据、逐张解码，核对裁图采用无损压缩。
双名单本身占用很小。Cloud 上限下能否处理超大图或很多并发用户，还需线上实测；本次未部署到你的云端。

本地验证：58 项测试通过，包括 45 项真实截图切图回归、4 项识别匹配回归、多图 AppTest、双名单解析、YY 人工候选确认及撤销、缓存失效、无损裁图和双 ID 导出。新功能 AppTest 使用 OCR 测试替身；未重新评测真实姓名识别准确率。
